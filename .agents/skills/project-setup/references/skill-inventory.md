# Environment skill inventory

Inspect the skills exposed by the current client and any repository-local skill directories. Use the client's skill listing or discovery tool when available; read each candidate's metadata and instructions before selecting it. A file on disk is not proof that the current client has loaded it. Record the name, source, availability in this session, trigger, and scope. If the client cannot expose its inventory, record that limitation and verify only the skills actually visible.

Match candidates to observed or planned technologies and to cross-cutting concerns such as tests, accessibility, security, or documentation. Explain how each selected skill should be invoked or applied. Recommend a new skill only when a real repeated coding convention is missing; state its intended scope and keep the proposal separate from installed skills.

Compare selected skills with `AGENTS.md`, the profile, agent TOMLs, and each other. Flag contradictory commands, incompatible framework versions, different ownership or approval rules, and overlapping skills that prescribe incompatible patterns. Quote or point to both sources and describe the effect on a real task. Ask the developer to decide the resolution; record the decision in the profile. Do not resolve a policy conflict by silently picking the instruction that appears most convenient. Higher-priority client or user instructions still apply, and a profile cannot override them.

Recheck the inventory on refresh because available skills may change with client, installation, or session. Discovery alone does not authorize skill writes. A user's explicit choice to create a domain skill during setup authorizes only that agreed skill; use `references/domain-skill-authoring.md` for its intake, quality checks and installation. Other installs or edits require their own request.

The pack bundles clean-code-architecture, frontend-design, testing, accessibility, angular-guidelines, and systematic-debugging. Inspect these alongside environment skills rather than assuming the bundled copy wins. Select clean-code guidance for code structure, frontend-design and accessibility for web UI, testing for meaningful verification, angular-guidelines for Angular 21 or after checking version compatibility, and systematic-debugging for bugs or unexplained failures. Installed does not mean applicable to every task. Report conflicting guidance and let the user decide. Do not generate a replacement for an adequate existing skill.

Domain skills are project specific: do not import a domain skill from an unrelated product. Ask for entities, invariants, validation limits, lifecycle transitions, errors, examples, and exclusions when canonical requirements cannot answer them. Propose a domain skill only for repeated guidance, source its rules from confirmed decisions, and evaluate valid, invalid, and boundary cases before claiming quality.
